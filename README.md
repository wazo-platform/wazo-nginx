wazo-nginx
==========

wazo-nginx is a Debian package that provides a basic configuration for the
nginx server used by Wazo.

# Logs

External requests (ports 80 and 443) are logged in `wazo.access.log`, internal
service-to-service requests (loopback only, port 80) in `wazo-internal.access.log`.

The default Wazo log format add additional information about
response time and status.

```
log_format main
    '$remote_addr - $remote_user [$time_local] "$request" '
    '$status $body_bytes_sent "$http_referer" "$http_user_agent" "$sent_http_x_powered_by" '
    '$request_length $msec $request_time $upstream_addr '
    '$upstream_response_length $upstream_response_time $upstream_status';
```

| Placeholder               | Description                                                       |
|---------------------------|-------------------------------------------------------------------|
| $remote_addr              | the source IP address of the client                               |
| $remote_user              | user name supplied with the Basic authentication                  |
| $time_local               | local time in the Common Log Format                               |
| $request                  | full original request line                                        |
| $status                   | response status                                                   |
| $body_bytes_sent          | number of body bytes sent to a client                             |
| $http_referer             | value of the Referer header                                       |
| $http_user_agent          | value of User-Agent header                                        |
| $sent_http_x_powered_by   | service name                                                      |
| $request_length           | request length (including request line, header, and request body) |
| $mesc                     | time in seconds with a milliseconds at the time of the log write  |
| $request_time             | request processing time in seconds with a milliseconds resolution |
| $upstream_addr            | the IP address and port of the upstream server                    |
| $upstream_response_length | the length of the response obtained from the upstream server      |
| $upstream_response_time   | time spent on receiving the response from the upstream server     |
| $upstream_status          | status code of the response obtained from the upstream server     |

## Masked secrets

`$request` is logged as `$customrequest`, which masks:

* wazo-auth tokens (`token=<uuid>` and `/token/<uuid>`)
* the wazo-provd provisioning key, i.e. the first path segment after
  `/device/provisioning/`

The same provisioning key is masked in the Referer (`$customreferer`).

The `provd` log format is the same as `main`, but uses `$provdrequest`, which
masks the first path segment of every request, and logs `-` as the Referer. It
is meant for the plain HTTP provisioning server of wazo-provd (generated by
xivo-config), where the provisioning key is the first path segment when
`http_auth_strategy` is `url_key`.

For the provisioning key, the logged request line is rebuilt from the normalized
`$uri` (percent-decoded, slashes merged, dot segments resolved), so it can differ
from the line the client sent. When nginx rejects a request before parsing its
URI, the whole request target is masked.

```
GET /device/provisioning/<key>/file.cfg HTTP/1.1  ->  GET /device/provisioning/XXXXXXXX/file.cfg HTTP/1.1  (main)
GET /<key>/file.cfg HTTP/1.1                      ->  GET /XXXXXXXX/file.cfg HTTP/1.1                      (provd)
```

## GoAccess log format

Logs can be analyzed with [GoAccess](https://goaccess.io) using the following
time, date and log format :

```
time-format %H:%M:%S

date-format %d/%b/%Y

log-format %h %^ %e [%d:%t %^] "%r" %s %b "%R" "%u" "%^" %^ %^ %^ %v %^ %T %^
```

Live report command line example :

```
goaccess --real-time-html --date-format '%d/%b/%Y' --time-format '%H:%M:%S' \
  --log-format '%h %^ %e [%d:%t %^] "%r" %s %b "%R" "%u" "%^" %^ %^ %^ %v %^ %T %^' \
  /var/log/nginx/wazo.access.log
```

# confd users cache

The internal entry (`127.0.0.1:80` and `[::1]:80`, loopback only) serves
confd under `/api/confd/`, from `locations/http-available/wazo-confd`.
`GET /api/confd/1.1/users` is cached for 60 seconds, keyed on the
`Wazo-Tenant` header and the full URI. Requests with a `uuid` filter, other
methods and all other confd paths go to confd without cache. The
`X-Cache-Status` response header shows `HIT`, `MISS`, `BYPASS`, `STALE` or
`UPDATING`.

Only wazo-dird must use it. A cache hit does not reach confd, so confd does not
check the token: any local process can read the cached listing. The cache is for
one tenant and holds directory data (names, numbers, e-mail addresses) in
`/var/cache/nginx/wazo-confd-users`.

To use it, set the `confd` block of the dird `wazo` source to
`{host: localhost, port: 80, prefix: /api/confd, https: false, version: 1.1}`
and restart wazo-dird. To stop, set it back to
`{host: localhost, port: 9486, prefix: null, https: false, version: 1.1}` and
restart wazo-dird.

Test with docker: `tests/test_users_cache.sh [nginx-image]`.
